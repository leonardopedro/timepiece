# `converted/` — prove2.me downloads converted to Lean 4.28.0

This folder holds the conversion of `Downloads/` (the prove2.me solution sources listed in
`Downloads/manifest.json`, 163 entries, 161 solution files) to this repository's toolchain
(`leanprover/lean4:v4.28.0` and the pinned Mathlib). It carries out Phase 1.5 of
`BOOKPROOF_SPLIT_PLAN.md`, with the landing zone moved from `BookProof/Toolbox/Prove2me/` to this
folder, as the conversion request asked.

## Status (2026-10-19)

* **All 161 solution files** listed in `Downloads/manifest.json` are converted and compile
  (`lake build Prove2me`, which also builds the platform modules they import).
* The prove2.me platform library that the solutions import, supplied as `Downloads/_deps/`
  (542 `Definitions.Def_*` and 181 `Theorems.Thm_*` modules), is converted under `Definitions/` and
  `Theorems/` with its module names kept (lake library `Prove2mePlatform`, aggregators
  `Definitions.lean` and `Theorems.lean`).  Everything compiles except the 299-module
  `Definitions.Def_OAIE3v2B*` chain (see below), which no manifest solution imports.
* `lake build Prove2me.Audit` prints the axioms of all 161 solutions and of the 161 registered
  platform statements they prove (322 declarations):
  * **122 solutions** use only `propext`, `Classical.choice`, `Quot.sound` (or a subset);
  * **39 solutions** additionally reach `sorryAx`, and in every case only through platform
    *statement stubs* `Theorems.Thm_*` (108 distinct stub theorems).  A `Thm_` module of the
    platform states a theorem and ends in `:= by sorry` by platform design; the accepted proof is
    a separate submission that is not part of the download (`Downloads/_deps/README.md`).  These
    39 conversions are therefore proofs *relative to the listed stub statements*, exactly like the
    originals on the platform.  `GAPS.md` lists, per solution, the stub theorems used (computed
    from the compiled terms by `scripts/prove2me_stub_cone.lean`, output
    `stub_dependencies.txt`).
  * Where a stub's own solution is among the downloads (26 cases) the import is re-pointed at the
    converted, proved solution, so no downloaded proof is replaced by a stub.

## Layout

| path | content |
|---|---|
| `Prove2me/<Group>/<Name>.lean` | the 161 converted solutions (module `Prove2me.<Group>.<Name>`) |
| `Prove2me/Shim/*.lean` | proved replacements for platform-Mathlib API missing from the pinned Mathlib (12 files, no `sorry`) |
| `Prove2me.lean` | aggregator importing all conversions and shims (lake library `Prove2me`) |
| `Prove2me/Audit.lean` | `#print axioms` for every solution and its platform statement (generated by `scripts/prove2me_audit.py`) |
| `Definitions/`, `Theorems/` | the converted platform library (`Downloads/_deps/`) |
| `blocked/FockLadders/OAI_Erdos3_….lean` | the one download that is prepared but not compiled (see below) |
| `diffs/<Name>.diff` | conversion record: unified diff, original download → converted file (161) |
| `GAPS.md` | solutions that use platform statement stubs, per solution and as an inverse index |
| `stub_dependencies.txt` | machine-readable form of the same data |

`<Group>` is the download group in CamelCase (`operator-qm` → `OperatorQm`). `<Name>` is the
platform theorem name with `.` replaced by `_`.

Build and audit:

```bash
lake build Prove2me           # all 161 conversions (+ the platform modules they import)
lake build Prove2mePlatform   # the whole converted platform library except the OAIE3v2B chain
lake build Prove2me.Audit     # prints the axioms of every converted theorem
```

## What a converted file contains

1. A provenance and attribution header: platform `theorem_id`, original name, statement author,
   solution author, submission id and acceptance date, literature source, platform Mathlib rev,
   the original path, and the Apache-2.0 notice (prove2.me public contributions,
   https://prove2.me/terms).
2. The verbatim solution source, with these changes:
   * the platform entry point `theorem solution` is renamed to `Prove2me.Solution.<Name>`, so that
     several conversions can be imported together;
   * `import Theorems.Thm_<X>` is re-pointed at the converted module of download `X` when `X` was
     downloaded;
   * the API drift between the platform Mathlib (`0df444a360ea`) and this repository's pin is
     repaired by hand (listed below).
3. The platform's registered formal statement (manifest `formal_statement`), under its original
   name (for example `FamousTheorems.krein_milman`), proved by the solution. This checks that the
   converted solution still proves the statement registered on the platform.

`scripts/prove2me_convert.py` writes only modules that do not exist yet, so hand edits are never
overwritten (unless it is run with `--force-all`).  `scripts/prove2me_diff.py` regenerates `diffs/`
and `GAPS.md`.

## Hand conversion edits

| file | edit | reason |
|---|---|---|
| `CstarGelfand/FamousTheorems_von_neumann_mean_ergodic` | `(f.eqLocus 1).orthogonalProjectionOnto x` → `(LinearMap.eqLocus f 1).orthogonalProjection x` (solution **and** platform statement) | the platform API name is not in the pinned Mathlib; the new form is exactly the conclusion of `ContinuousLinearMap.tendsto_birkhoffAverage_orthogonalProjection` |
| `UnferBayes/BanditAlgorithm_gaussian_relative_entropy_formula` | local lemma `Prove2me.Shim.rnDeriv_eq_div`, proved from `Measure.rnDeriv_mul_rnDeriv'`; `rw [hx, h1, h2]` → `rw [hx]; exact congrArg₂ (· / ·) h1 h2` | `Measure.rnDeriv_eq_div` does not exist in the pinned Mathlib |
| `CrouzeixConvex/Grunbaum2003_bounded_closed_convex_extreme_representation` | `(Finset.finite_toSet _).isCompact_biUnion` → `Finset.isCompact_biUnion`; `isCompact_stdSimplex ℝ (Fin n)` → `isCompact_stdSimplex (Fin n)`; `continuous_finsetSum` → `continuous_finset_sum` | lemma signature/name drift (the first one caused a heartbeat timeout) |
| `CrouzeixConvex/Grunbaum2003_compact_convex_nonpolytope_infinite_extreme` | `(h.isCompact_convexHull ℝ)` → `h.isCompact_convexHull`; the file's own platform theorem now cites the renamed solution, so no statement block is appended | the field is now implicit; the solution file already declares the platform theorem |
| `UnferSirk/FamousTheorems_eigenvalue_mem_ball` | the duplicate `universe u_1 …` line is dropped from the appended statement | the solution body already declares those universes |

The table above records the edits of the first 21 (self-contained) conversions.  For the other
140 solutions and the platform library the repairs are systematic and are recorded as follows
(`diffs/` holds the complete per-file record):

* **token-level API drift** (platform Mathlib `0df444a360ea` → pinned Mathlib): the 16 regex
  replacements of `scripts/prove2me_drift.py`, each with its reason (for example
  `*finsetSum*` → `*finset_sum*`, `Filter.limUnder` → `limUnder`, `convert!` → `convert`);
* **missing Mathlib API**: proved shims in `Prove2me/Shim/` (modular discriminant `Δ` built from
  `E₄`, `E₆`; singular values; exterior-algebra basis; Poisson/Herglotz kernels; Schwartz
  translation; convergence in distribution; and small lemmas), imported where the platform file
  used the missing API.  A statement that mentions a shim definition is faithful to the original
  only insofar as the shim agrees with the platform-Mathlib definition; each shim documents the
  definition it reproduces;
* **name clashes between solutions**: the platform compiles each solution alone, so several
  solutions of one author repeat helper declarations under the same name (`RPL2.g`,
  `SVDProbe.gram`, `gexp_add`, …; 76 names).  To let the aggregator import all of them, the
  repeated helper is made `private` in every module but the first (`scripts/prove2me_privatize.py`);
  no statement or proof changes.



## The one file that is not compiled

`Downloads/` contains one solution file that has no entry in `Downloads/manifest.json`:
`fock-ladders/OAI.Erdos3.VectorPolynomial.sharedWidthPreparedCenteredShortForecastProductiveGoodModelInterface_of_goodModel_s2.lean`.
It imports `Definitions.Def_OAIE3v2B290/291`, whose cone is the 299-module
`Definitions.Def_OAIE3v2B*` chain (21.6 MB of platform text, import depth 30).  The chain is
converted text under `Definitions/`, but it does not compile against the pinned Mathlib: building
it stops at 32 frontier modules with API-drift errors (for example `PowerSeries.log`,
`Finsupp.coeff`, `Matrix.det_of_isUpperTriangular`, `Submodule.baseChange_mono` are missing from
the pinned Mathlib), and the remaining modules are blocked behind them.  The prepared text of the
solution is in `blocked/FockLadders/`; it is not a module of any lake library.  The manifest also
records three entries without a solution file: `OAI.DirectCrouzeix.FaberCalculus` (a platform
definition), plus `courant_fischer` and `cauchy_interlacing_sorted`.

## Routing note (BOOKPROOF_SPLIT_PLAN.md §8)

The sibling-earmarked groups (`unfer-sirk`, `unfer-bayes`, `logos-confluence`, `arctic-crypto`)
are converted here like every other group, but they are **not** wired into `BookProof/`. The
library `Prove2me` is separate from `BookProof` and is not a default target. Adopting a
conversion into `BookProof/Toolbox/` (or into the `Layout/` zero-import channel for `unfer`)
remains a later, deliberate step.
